Retrieval Augmented Generation: A Reading Map Method score 0.146

## Method We group systems by retrieval unit. Passage-level retrieval offers precise evidence spans, while document-level retrieval preserves broader context. Dense bi-encoders learn a shared embedding space for queries and passages; sparse lexical retrieval such as BM25 remains strong for rare terms, identifiers, and exact phrases. Hybrid fusion combines the two candidate lists, commonly with reciprocal rank fusion (RRF), which is robust because it uses ranks instead of incomparable score scales. A reranker may then refine the top candidates before generation.

## Abstract Retrieval augmented generation (RAG) couples a document retriever with a language model so that answers can be grounded in external evidence rather than model parameters alone. This reading map organizes the design space along three axes: what is retrieved, when retrieval happens, and how retrieved evidence is fused into generation. The central claim is that most quality differences between RAG systems come from retrieval granularity and evidence selection, not from the generator. We use this map to compare sparse retrieval, dense retrieval, and hybrid fusion.

## Limitations A cross-encoder reranker cannot fix a candidate list that misses the relevant passage entirely. Long passages increase cost and may exceed the reranker's input limit. Training hard negatives from the same retriever can overfit to its failure modes. The notes do not cover learned fusion of multiple rerankers, and nDCG rewards graded relevance that our small corpus does not provide.

Reranking for Retrieval Pipelines Method score 0.139

## Method A cross-encoder reads the query and passage together, allowing token-level interactions that a bi-encoder cannot capture. The input candidate list is produced by BM25, a dense retriever, or a hybrid of both. We compare two-stage and three-stage pipelines: retrieve top 50, rerank top 20, then pass the best 5 to the generator. Training uses query-passage pairs with hard negatives mined from the first-stage results. Reranking scores are not comparable across queries, so pipelines use them only to order candidates within one query.

## Abstract Chunking decides what a retriever can see. A chunk that is too small loses the context needed to interpret a claim, while a chunk that is too large dilutes its embedding and wastes the generator context window. This note compares fixed windows, sentence packing, and semantic boundaries on technical documents with headings, formulas, and references.

Reranking for Retrieval Pipelines Abstract score 0.015

## Abstract First-stage retrieval must be cheap, so it usually trades precision for recall. A reranker revisits a small candidate list and scores each query-passage pair with a stronger model. The core problem it solves is context pollution: irrelevant passages consume the generator's limited context window and invite unsupported claims. Reranking is therefore a precision filter placed between retrieval and generation.

## Takeaways Start from retrieval quality, then improve the generator. Keep a lexical baseline, add dense retrieval when paraphrase matters, and fuse by rank rather than raw score. Always preserve a path from an answer sentence back to a source passage and its line numbers.

Grounding Generated Summaries with Evidence Spans Method score 0.014

## Method Retrieved chunks are numbered C1 through Cn and passed to the generator with a strict instruction to cite them. The validator parses citation markers, checks them against the chunk set, and computes citation coverage as cited conclusion sentences divided by total conclusion sentences. Unknown markers are removed from the visible summary and recorded in a report. If coverage falls below a threshold, or the model call fails, the system returns an extractive summary built from the chunks, with the same citation numbers. Prompt hashes and latency are logged without storing credentials.
