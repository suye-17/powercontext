# 记忆伪造师

用三句话伪造你的人生：一本会当真、会对账、还会记前科的记忆账本。

- 赛题：Dify × OceanBase「Just for Fun——用 Dify 做一个好玩的智能应用」
- 技术组合：**Dify（Chatflow，编排）+ PowerContext 1.2.0（唯一持久层）**；未使用 seekdb，未使用知识库与 Embedding/Rerank

## 1. 作品与玩法

你是退休记忆修复师的"新客人"。它有一本账本，替人归档一生。你有三句话的机会，把自己的过去说成任何样子；它会认真替你归档、照着改口、从此认定你就是那个人。三句话后，它合上笔，翻开账本跟你**对账**。

四个好玩点：

1. **你的谎被当真**：随口一句"我是你失散多年的师兄"，它当场合上账本、改口叫你师兄。
2. **你的谎会自相矛盾**：说"我十年前在东京学剑"，又说"我从没离开过这座城"，账本里两条原话并存；对账时它逐条念出来，问"你到底是谁"。
3. **它记得有人撒过谎**：对账结论、矛盾点写进你自己的账本；同时一条"此人有前科"的档案写进**总账本**——换个代号重开，新客人也能看见前任的档案。
4. **同一个代号，它认得你**：代号即身份（幂等 scope）。开新会话、重新报同一个代号，它仍能从账本里想起你说过的话。

体验方式：Dify 的 WebApp 就是全部入口。开场白给出"报代号 → 说三句话"的引导，右上角还预置了三条示例输入。

## 2. Dify 与 PowerContext 的分工

| 组件 | 承担的工作 |
| --- | --- |
| **Dify（Chatflow，29 个节点）** | 表单输入、代号规范化、条件分支（首访、第三句、是否已对账、是否记录矛盾）、两次模型调用（扮演修复师 / 终局对账）、6 次 PowerContext HTTP 调用、结果输出 |
| **PowerContext 1.2.0** | 唯一持久层：代号 → scope（幂等身份）、玩家账本（主张/登记档案/对账结论/矛盾）、总账本（前任前科）、按话语召回、全量账本读取 |

Dify 侧不保存任何应用状态：跨轮次信息全部来自 PowerContext，Dify 只用平台自带的会话计数 `sys.dialogue_count` 判断"这是第几句"。

记忆类型（`kind` 是 PowerContext 的自由字符串，用来表达游戏语义）：

| kind | 写入位置 | 含义 |
| --- | --- | --- |
| `truth` | 玩家账本 | 首次来访的登记档案（终局对账的底牌） |
| `claim` | 玩家账本 | 玩家每句话的**原话**，逐条存档 |
| `verdict` | 玩家账本 | 一次对账的结论；它的存在即"已经对过账"的判定依据 |
| `contradiction` | 玩家账本 | 对账时确认的矛盾点（仅在有矛盾时写） |
| `ledger` | 总账本 | 前任访客的前科档案，跨代号可见 |

## 3. 运行环境

| 项目 | 版本 / 说明 |
| --- | --- |
| Dify | 作者在 **Dify Cloud** 验证；DSL 版本 `0.4.0`，也可导入自托管 Dify（社区版 ≥ 1.x） |
| PowerContext | `1.2.0`（`uv tool install "powercontext[cli,server]==1.2.0"`），Python 3.11+，SQLite |
| 模型 | 任意 OpenAI 兼容对话模型。作者实测 `deepseek-v4-flush` / `deepseek-chat`；**PowerContext 侧不需要任何模型** |
| Embedding / Rerank | **未使用**。PowerContext 的召回在没有模型时自动走全文检索 |
| 自定义插件 | 无。只用 Dify 内置节点（开始、HTTP 请求、代码、条件分支、LLM、直接回复） |
| 自定义后端 / 前端 | 无。`scripts/` 里的两个 shell 脚本只用于初始化和清零，不参与应用运行 |

网络条件：

- **路径 A（Dify Cloud）**：PowerContext 在本机运行，需要一条公网可达的 HTTPS 地址（作者用 `cloudflared tunnel --url http://127.0.0.1:8000` 的临时隧道）。Dify Cloud 出站必须能访问该域名。
- **路径 B（自托管 Dify）**：Dify 与 PowerContext 在同一台机器或同一内网，HTTP 节点直接填宿主可达地址（如 `http://host.docker.internal:8000`），无需公网。

## 4. 从零跑通

### 4.1 启动 PowerContext

```bash
# 安装（已装可跳过）
uv tool install --force "powercontext[cli,server]==1.2.0"

# 用独立数据目录启动，避免和本机其他数据混在一起
mkdir -p ~/memory-forgery/home
cd ~/memory-forgery            # 重要：这里不要有 .env，否则会被自动加载
POWERCONTEXT_HOME=$HOME/memory-forgery/home powercontext server run --no-env-file --port 8000

# 另开一个终端验证
curl --fail --silent http://127.0.0.1:8000/health/live    # {"status":"ok"}
```

### 4.2 初始化总账本（可选但推荐）

```bash
./scripts/seed.sh http://127.0.0.1:8000
```

脚本幂等：总账本里已有预置档案时不会重复写入。预置的两条前任档案让**第一位**玩家也能看到"账本第一页有人写过东西"。

### 4.3 让 Dify 能访问 PowerContext

- 路径 A（Cloud）：
  ```bash
  cloudflared tunnel --url http://127.0.0.1:8000
  # 记下输出的 https://xxx.trycloudflare.com
  ```
  隧道地址每次重启都会变，属于运行期配置，不写进仓库。
- 路径 B（自托管）：跳过此步，直接使用内网地址。

### 4.4 导入 DSL

1. Dify → 工作室 → 创建应用旁的下拉 → **导入 DSL 文件** → 选 `dsl/memory-forgery.yml`
2. 打开应用 → 左侧「环境变量」→ 把 `POWERCONTEXT_BASE_URL` 改成你的地址（**结尾不要带斜杠**）
3. 两个 LLM 节点（「修复师归档」「终局对账」）如果显示未选择模型，各选一次你的对话模型
4. 右上角「发布」→ 打开 **WebApp**（应用入口）

> `dsl/smoke.yml` 是可选的最小连通性自检：导入后只改环境变量、发任意一句话，回复里出现 `scope_id` 即说明 Dify 已连通 PowerContext（不调用模型）。

> **导入前确认工作区还有空位**：Dify Cloud 免费版最多 5 个应用，达到上限时导入按钮会置灰并提示「您已达到此计划上构建应用的限制」。请先删除不再使用的应用，或改用自托管 Dify（社区版无此限制）。

### 4.5 恢复初始状态

```bash
./scripts/reset.sh            # 停止服务、清空数据目录
# 然后按 4.1 重新启动、按 4.2 重新播种
```

或只换一个代号重开：换代号即全新账本，不必清库。

## 6. 已知限制

- 三句话后进入对账。第 4 句起只回固定文案（"账本已经合上了……"），要重来请换代号或开新会话。
- "前科"与矛盾记录依赖模型在终局对账时给出结构化矛盾点。模型若只输出散文，账本仍会写入主张与对账结论，但不会记录矛盾与前科。
- 隧道地址是运行期配置，重启即变；仓库里只有占位值。
- Dify Cloud 出站受限时（企业网络、动态域名被拦），请改用路径 B。
- 应用不校验代号真实性：代号就是身份，写什么就是什么——这正是本题的玩法。
